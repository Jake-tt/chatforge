# 보완 계획: 아키텍처 리뷰 검증 결과와 PR 순서

[`261028_architecture_review.md`](261028_architecture_review.md)의 지적을 코드로 직접 확인한 결과와, 이를 반영한 PR 계획입니다. 확인 기준은 `main`(PR #7 머지 후)입니다.

## 1. 취약점 7건 검증

| # | 지적 | 판정 | 근거 / 정정 |
|---|---|---|---|
| 1 | `X-Forwarded-For` 스푸핑으로 게스트 생성 제한 우회 | **맞음** | `Dockerfile`이 `--forwarded-allow-ips="*"`로 실행. uvicorn 0.54는 이 설정에서 XFF의 **맨 왼쪽** 값을 클라이언트 IP로 씀(`proxy_headers.py` `get_trusted_client_address`). 맨 왼쪽은 클라이언트가 임의로 넣을 수 있음. 로그인·가입에 rate limit이 없는 것도 맞음 |
| 2 | 스트리밍 중 병렬 요청으로 쿼터 초과, 같은 대화 동시 요청 시 순서 꼬임 | **맞음** | 쿼터 확인(`conversations.py:146`)은 시작 전 한 번, 차감은 답변 저장 시. 같은 대화에 동시 요청하면 `user, user, assistant, assistant` 순서가 됨 |
| 3 | holdback 구간에서 끊기면 user 메시지만 남고 제목·과금이 틀어짐 | **맞음, 일부 정정** | `AgentStream.partial`이 `_held`를 빼고 계산(`stream.py:46`). 그래서 80자 전에 끊기면 assistant가 저장되지 않음. 그러면 다음 턴의 첫 메시지 판정(`seq == 1`)이 영영 거짓이 되어 제목이 생기지 않음. 과금도 과소 추정. **정정**: Anthropic API는 연속된 user 턴을 거부하지 않고 합쳐서 처리하므로 "API 에러"는 과장. 실제 영향은 제목 누락, 과소 과금, 같은 질문의 중복 전달 |
| 4 | `asyncio.shield`의 불완전한 보호 | **맞음 (낮음)** | Python 문서는 `shield`에 넘긴 태스크의 참조를 보관하라고 권고. 지금은 코루틴을 바로 넘겨, 바깥 태스크가 취소되면 안쪽 태스크를 강하게 붙잡는 참조가 없음 |
| 5 | 요약이 system 프롬프트에 들어가 캐시가 갈림, 도구 라운드 결과에 breakpoint가 없음 | **앞 절반은 효과 작음, 뒤 절반은 맞음** | 요약이 바뀌면 앞쪽 메시지도 함께 잘려 나가므로 prefix는 어차피 바뀜. 정적 지시문(system + TOOLS_NOTE)만 따로 캐시하려 해도 Opus 5.5의 최소 캐시 크기(512토큰)보다 작아 이득이 없음. 반면 ReAct 2·3라운드는 도구 결과를 매번 캐시 없이 다시 보내는 게 맞음. 마지막 scratch 메시지에 breakpoint를 두면 해결됨(최대 4개 중 3개 사용) |
| 6 | ReAct 도구 결과에 길이 예산이 없음 | **맞음** | coordinator는 `grounding_char_budget`을 지키지만, 도구는 `ToolOutput.of(hits)`로 원문 전체를 넣음. 지난 대화 검색은 메시지 전문을 반환 |
| 7 | Redis 소켓 타임아웃 없음, 한 번 실패하면 10초 동안 전체 차단 | **맞음** | `Redis.from_url`에 타임아웃 설정이 없음(`main.py:43`). `RedisGuard`는 오류 1회로 10초 동안 열림 상태가 되고, 그동안 rate limit은 fail-open으로 무력화됨 |

## 4. 결정 (2026-10-28)

1. **응답이 하나도 생성되지 않은 턴의 user 메시지는 삭제한다.** 대화를 원래 상태로 되돌리고, 사용자에게는 `error` 이벤트로 알린다.
2. **PR 순서는 위 표대로** F → G → H → I → E → J → K.
3. **PMC 본문 수집은 사용자가 직접 실행한다.** 스크립트는 PR E 브랜치에 먼저 올린다. 요청 상한·디스크 캐시·429 백오프를 갖추고, NCBI 요청에 이메일을 넣지 않는다.
